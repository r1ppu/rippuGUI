# 03 調教ステートとメモリ（コア設計メモ）

「調教で反応が変わる」を、感覚ではなく **状態変数** で持つ。

## ステート例（MVP）
| 変数 | 意味 | 変化要因の例 |
|---|---|---|
| trust | 信頼 | 一貫した優しさ、約束を守る |
| affection | 好意 | 会話の親密さ、褒め |
| obedience | 従順さ | 指示への従い、報酬/罰の一貫性 |
| resistance | 抵抗 | 急な要求、無視、乱暴な扱い |
| mood | 今の気分 | 直前ターンのイベント |

※数値は 0–100 などで十分。毎ターン少しずつ動かし、発話スタイルに反映。

## メモリの分け方
1. **Working memory**: 直近 N ターン（そのままプロンプトへ）
2. **Episodic memory**: 「昨日こうされた」などの要約（RAG）
3. **Profile memory**: ユーザーの好み・呼び名・境界線（常時注入）
4. **Policy memory**: セーフワード、やってよい/だめ（絶対優先）

## 実装の落とし穴
- ステートをプロンプトに書いただけだとドリフトする → **コード側でclampして強制**
- 全部を長期記憶に入れると汚染 → **要約エージェントで圧縮**
- 「エロ反応」だけを強化すると人格が壊れる → **trust/affection とセットで更新**

## 参考システム（詳細は papers / opensource）
- Nadine: LLM + RAG記憶 + 感情内部状態
- 認知ロボット人格シミュレーション: 短期/長期記憶と意図・感情の分離
- EgoMem系: リアルタイム対話向けの生涯記憶（後段で参考）
